# Fitness tracker: hub login, implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The tracker logs people in through the family hub (key `fitness`, home only), takes its people from the hub
and drops its own passwords.

**Architecture:** The backend asks the hub through family-hub's client package (`family_hub_client`), keeps the hub's
people in `users.json` (linked by `hub_id`) and resolves every request to a local person id; endpoints stop taking
`user_id`. The frontend sends the hub cookie to `/api`, sends the browser to the hub on 401 and shows its own pages for
"no access" and "hub unavailable".

**Tech Stack:** FastAPI, filelock, family-hub-client (stdlib only), pytest; React 19, axios, Vite, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-10-hub-login-design.md`

## Global Constraints

- App key `fitness`; CSRF header `X-Requested-With: fitness`; renew header `X-Hub-Renew: 1`; cookie `hub_session`.
- Error body `{"detail": {"code": "<code>"}}` with `not_logged_in` (401, plus `WWW-Authenticate: Bearer`), `csrf` (403),
  `no_access` (403), `hub_unavailable` (503).
- Any request with a `Cf-Connecting-Ip` header is 401 `not_logged_in`, whatever else it carries.
- `backend/requirements.txt` pins
  `family-hub-client @ https://github.com/FrankAndreas/family-hub/archive/62f20a6de5eaf2ca7c8823d4783842696ab607df.tar.gz#subdirectory=client`
  (the siblings' commit); `bcrypt` and `PyJWT` go away.
- People refresh: at most every 60 s, one at a time, 10 s backoff after a failure; "not refreshed yet" is `None`.
- Local ids never change; a new hub person gets `hub<hub id>` (e.g. `hub7`). Name linking only at the first sync.
- Settings: `HUB_URL`, `HUB_PUBLIC_URL`, `HUB_APP_KEY` (read by the client package).
- The repository is public: tests and docs use invented people and placeholders (`<domain>`, `<NAS_IP>`).
- Lint: `ruff check backend`, `npm run --prefix frontend lint` (zero warnings), `npm run --prefix frontend build`.

## Review Focus

1. **The hub answers an empty people list** (the asker lost access a moment ago): nobody is hidden, `users.json` is
   unchanged. Test in Task 1.
2. **Two hub people, or two local entries, with the same name at the first sync:** neither is linked by name (they
   get new `hub<id>` entries / stay unlinked), so nobody gets someone else's workouts. Test in Task 1.
3. **A person removed in the hub and given access again:** the same entry (by `hub_id`) comes back active, with their
   workouts. Test in Task 1.
4. **The hub is down on the very first request:** 503 `hub_unavailable`, `users.json` untouched, the next request
   within 10 s doesn't ask the hub again. Test in Task 2.
5. **An old `fitness_token` left in a browser's local storage:** ignored and removed on load; no Authorization header
   is ever sent. Test in Task 5.

### Task 2: Hub login on every endpoint; passwords gone

**Files:**
- Create: `backend/auth.py`
- Modify: `backend/main.py`, `backend/test_main.py`, `backend/test_hub_login.py`
- Delete: `backend/set_password.py`

**Interfaces:**
- Consumes: Task 1's `hub.client`, `hub_people.refresh/local_id/wait_for_running`, conftest `login`.
- Produces:
  - `auth.Person` (frozen dataclass: `id: str`, `name: str`).
  - `auth.get_current_person(request: Request, response: Response) -> Person` (plain `def`, so it runs in a worker
    thread). Order: `Cf-Connecting-Ip` present → 401; Bearer, else cookie `hub_session`, else 401; cookie + method not in
    GET/HEAD/OPTIONS + header ≠ `fitness` → 403 `csrf`; `hub.client.session(...)`; no person → 401; no access → 403
    `no_access`; `refresh(login)`; `local_id(person.id)` missing or the entry's name ≠ `person.name` →
    `refresh(force=True)`; still missing → `wait_for_running(hub.TIMEOUT_SECONDS)` and look again; still missing →
    403 `no_access`. `HubUnavailable` → log a warning (never the token) and 503 `hub_unavailable`. `session.renew` →
    `response.headers["X-Hub-Renew"] = "1"`.
  - `GET /me` → `{"id": person.id, "name": person.name}`; `GET /hub` (no login) → `{"login_url": public_url,
    "logout_url": public_url + "/logout"}`.
  - `POST /workouts` body without `user_id`; `GET /workouts?date_from&date_to`, `GET /workouts/{date}`,
    `GET /records` without `user_id`. Each uses `person.id` for the folder.
