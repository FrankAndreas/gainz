# Themes, step 6: fitness-tracker – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The tracker moves from its own CSS (`index.css`, ~590 lines, 51 classes) to Tailwind v4 with
`family-hub-theme` (the user's choice: fully on Tailwind), shows the person's theme from the hub, and gets browser
tests first, since its whole styling is rewritten.

**Architecture:** `/me` returns `theme` straight from the hub session (`session.person.theme`: fresh on every
request, nothing stored). A Playwright setup like family-planner's (its own family hub from the family-hub checkout,
backend, Vite) pins today's behaviour before the rewrite. Then Tailwind v4 (`@tailwindcss/vite`), the package, and
`App.tsx` rewritten from the CSS classes to Tailwind with roles.

**Tech Stack:** FastAPI, pytest, ruff; React 19, Vite 8, Tailwind v4, vitest, Playwright.

**Spec:** `family-hub/docs/superpowers/specs/2026-11-28-themes-design.md` ("fitness-tracker has no Playwright tests yet:
its pull request adds a small setup ... with a test per screen").

## Global Constraints

- Package `theme-v1.0.0` release URL; client `family-hub-client` at `7a9848864c6fad37f791f8ed0f3d4521c4276936` (1.2.0).
- The e2e backend never touches `backend/data` (real workouts): `storage.DATA_DIR` follows env `DATA_DIR` when set.
- The look stays Aurora (the app already copies it); fewer shades; before/after screenshots in the PR.
- No palette classes, hex or `rgba()/hsl()` in `.tsx`; `check-colors.mjs` in `lint`; the remaining CSS is the
  package import plus app rules on `var(--fh-*)` only.
- Lessons from the other apps: text-page on (nearly) solid light fills; near-opaque surfaces → `bg-page/<opacity>`;
  polled blur checks; no test locates by colour or CSS classes; hovers never equal to base.
- CI: `npm ci --ignore-scripts` stays (prebuild still runs with `npm run build`); a new `e2e` job.

## Review Focus

1. Hub sends no or an unknown theme → `aurora`.
2. The rewrite keeps every behaviour the old classes carried: focus rings, disabled states, the record (🏆) highlight,
   the week navigation, error and success messages.
3. The phone layout (the tracker is used on phones) has no horizontal scrolling and finger-sized targets.
4. The gradient title and primary button stay readable (contrast).
5. The e2e data folder is temporary and removed on each run.
